## 同类任务开始时

1. 读相关案例的失败表现和未验证项，确认本次用户的内容、参考风格与交付要求。历史个案不替代当前要求。
2. 先用合成数据复现时间映射或设置问题，再决定改哪一处。剪辑时区分原片秒和成片秒；做重录取舍时对照原声，不能只看一次整片ASR。
3. 改代码运行案例列出的相关回归；新增变化或失败才扩大检查。按 [贡献规范](../../CONTRIBUTING.md) 完成必要的项目检查。
4. 交付分别说明文件可播放、字幕与剪口、画面与节奏验证到哪里。测试数、抽帧和音频相同都不能代替整段表达的判断。

## 新问题怎样留下来

在 `docs/experience/` 增加或更新一份短案例，索引加一行即可。每案记录：用户可见失败、合成复现、确认原因与推测、修复文件、回归命令、操作规则、未验证项。相同问题直接更新原案，不另起一套日志或评分体系。

公共文档只放可公开的机制与合成例子。私人证据留在被Git忽略的 `inspection/` 或当前任务目录；公共案例只引用相对的本机证据清单，不嵌入原话、原片、聊天或个人绝对路径。先写清楚观察，再决定能否将它提升为默认配置、代码修复或操作规则。

## 口播精剪的当前边界

“口播精剪”已接入本地词级识别、前后版本对齐、独立窄窗识别与声学剪口验证。真实原片通过编辑器入口新建本地分析作业，得到19项候选：1项满足自动删除条件，18项保留待复核。自动应用后，一次撤销恢复原片段和全部字幕；返回项目库再重开，逐项确认仍与基线一致。验证时没有启用Gemini或播放试听，不能据此宣称听感正确、重录全部识别或“一键全清”。私人操作记录及截图见本机证据清单。

现有相同字幕候选提示与这条分析流程分别说明。机制和限制见[口播精剪说明](../retake-analysis.md)，安全应用层回归见[retake-plan](../../tests/retake-plan.test.mjs)。继续保留原片、可撤销取舍和结果对照；回归覆盖改词重录、跨句停顿、否定词、数字及专名，避免只比较文字长度就选版本。近义改说、完整重复、保护词变化与证据不足的候选仍需原声复核。

更新：后续已加入跨停顿长词的独立重读与多词时间停顿保护，并交付逐项取舍的整条精剪修复版及少量独立试听点。旧19候选/1自动记录是历史基线；修复发现能力、具体视频取舍和通用自动批准能力分开验收，见REA案例末节。
