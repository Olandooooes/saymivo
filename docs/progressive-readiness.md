# 说明板与任务轨道的完整阅读检查

现有 `ProgressiveUiScene` 与 `TaskTracksScene` 保留原生机制，并增加 `onReadiness({status,issues,canApply:false,uiAccepted:false,needsFaceReview:true})`。中央工作台仍负责真实原片、资料加载、绝对源身份与实际完整预览凭证；这两类组件的 ready 只说明当前字体与保留时段下的内部文字/数字检查通过。

两类已经包含在统一动效参数页的22项实验机制中，并接入中央原生就绪回报。原生 `canApply=false` 不等于参数页没有应用入口：参数页须取得实际完整循环、当前DOM与场景快照核验产生的不可伪造会话凭证后，才允许应用本场及一次撤销。注册、配置有效、原生ready和实际UI验收分别判断。

两类都需要显式 `copyWindow:{atMs,endMs,rect}`。窗口内容由 renderer 从本场 title/body、全部原节点 text/detail/bullets 与可编辑 annotation 取得；未映射到元素或任务行的节点也会显示。使用实际加载字体逐页绘制与检查，绝不把隐藏 DOM 字符串算作显示。原生字段和最终数字字形也全部测量，缺任意回报、字体改变、旧测量或不可读页面都不显示旧图。

窗口必须位于原生动作前，不能隐藏元素入场/填写/聚焦/问题标记、任务段描画/着色、游标或日历翻页。任务轨道另留一秒静态总览。已有早起点配置不会被自动后移或压缩；需要作者明确调整时点或拆场。标题、节点、阶段标签和日历标签使用各自真实可见时窗；多页填写从自己的第一页开始，每页全文出现后按保留范围和速度核算阅读时间。完整游标、填写、翻页等动作及终态停留也必须保留下来，不能因为原文已出现便放行剪掉一半的动作。

人物保护与中央插槽使用相同默认 `sceneSpeakerLayout/speakerBox`，或全部已知人物窗关键帧的包络；正文、数字、图解和日历框不得进入人物或底部字幕区域。未知全幅人物没有自动安全承诺。任务日历增加可编辑 `calendar.rect`，明确整数日数和顺序时点；数据、单位、来源、任务区间或进度值仍须作者提供，不从口播推造实测事实。说明板保留中性解释形式，元数据中的示意说明不烧入固定生产角标。

`dynamic-motion-library` 两个 constructor 已带完整正文窗口和避开标题的面板草稿，控件可编辑阅读时窗、实际动作时点、日历框及 annotation。所需数值/时间域/标签仍留空待填；构造器不会为了可用而生成统计或执行结果。

回归：`tests/progressive-readiness.test.mjs`、`tests/progressive-scenes.test.mjs` 与相关 registry 测试。新增回归执行实际 renderer 分支和实际可见页切换，但字体/媒体使用明确合成替身。当前真实UI保存记录仅覆盖 emphasis、cumulative、ROI 三类，共8场；说明板和任务轨道的实际字体、原片、完整循环与工作台应用仍待各自验收。早期“SSR 有全文字符串”测试已改为缺失完整阅读合同必须 blocked。
