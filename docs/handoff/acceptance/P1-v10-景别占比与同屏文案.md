# P1-v10 景别占比、同屏文案、空卡片

用户已验收 v9。这一轮只改工作台通用起草和校验，不改景别倍率，不改 91.37 秒粗剪，不渲全片。用户还没看这一版。

## 改了什么

- `config/style.json` 的 `person.budget`：拉远时间占比下限 85%，推近上限 5%，每次推近不超过 2.2 秒，两次推近至少隔 24 秒，小窗每次不超过 2.0 秒。拉远仍是 0.80× 偏侧，居中 0.85×，推近底数仍是 1.08×，上限仍是 1.10×。
- 文字密集的镜头不推近。页面只有在拉远占比还守得住时才用小窗；守不住就退回拉远上的单行大字。小窗若短于所在镜头，剩下的时间回到拉远，避免小窗把整段镜头都占掉。
- 推近叠加上跳切和漂移之后，缩放不超过 `cover × 1.10`。拉远的 0.80× 不受这个上限影响。
- 同一屏的标题、大字、卡片要点来自同一句或同一个语义单元，顺序跟口播一致。互不从属的几句不再堆进同一张侧栏。一句拆成的两半留在同一个画面，并保留到这个意思结束，不会在下一个镜头再出现一次。卡片至少两行；只有一行时改成单行大字。卡片高度按行数收缩。本机模型给出的幻灯片仍过 `validatePlan`：要点按原句顺序重排，少于两行的卡片丢掉。

## 怎么验证

`python3 tools/koubo-port/pipeline/test_autocut.py` 通过。合成目录稿（150 秒）拉远 86.3%，推近 5.0%，小窗 6.7%，15 个模板都出现，文案配对检查为空，没有不足两行的卡片。同一套句子放在 91.366 秒的时钟上：拉远 85.3%，推近 2.6%，小窗 8.8%。清晰填边比值仍是 0.727 对 0.008，倍率仍是 0.80 / 1.08。

`npm run check`：1241 项，1235 通过，0 失败，6 跳过，vite build 成功。

## 这一轮没有重渲

这台环境没有私人原片（sha256 `0993291b174ac22da82fe44676c322eaa1a003d9e39c68a7b4a16b6bb7cbebd0`），也没有剪后画面和字体。约 12 秒、22 秒、42 秒、50 秒、62 秒的关键帧和中段 20 秒样片没有重渲。上面的占比是合成草稿，不是这条口播的成片统计。

v9 里约 12 秒和约 22 秒已经是 0.80× 拉远。这一轮不把倍率再调小，那两帧的人头不会再变小。约 42 秒在 v9 是推近；新的占比会把这种文字密集的镜头留在拉远或小窗里，推近只留给很短的单行。
