# P1-v10 景别占比、同屏文案、空卡片

用户已验收 v9。这一轮只改工作台通用起草和校验，不改景别倍率，不改粗剪规则，不渲全片。用户还没看这一版。原来那份 Paraformer 字表上的成片仍是 91.37 秒。

## 改了什么

- `config/style.json` 的 `person.budget`：拉远时间占比下限 85%，推近上限 5%，每次推近不超过 2.2 秒，两次推近至少隔 24 秒，小窗每次不超过 2.0 秒。拉远仍是 0.80× 偏侧，居中 0.85×，推近底数仍是 1.08×，上限仍是 1.10×。
- 文字密集的镜头不推近。页面只有在拉远占比还守得住时才用小窗；守不住就退回拉远上的单行大字。小窗若短于所在镜头，剩下的时间回到拉远，避免小窗把整段镜头都占掉。
- 推近叠加上跳切和漂移之后，缩放不超过 `cover × 1.10`。拉远的 0.80× 不受这个上限影响。
- 同一屏的标题、大字、卡片要点来自同一句或同一个语义单元，顺序跟口播一致。互不从属的几句不再堆进同一张侧栏。一句拆成的两半留在同一个画面，并保留到这个意思结束，不会在下一个镜头再出现一次。卡片至少两行；只有一行时改成单行大字。卡片高度按行数收缩。本机模型给出的幻灯片仍过 `validatePlan`：要点按原句顺序重排，少于两行的卡片丢掉。

## 怎么验证

`python3 tools/koubo-port/pipeline/test_autocut.py` 通过。合成目录稿（150 秒）拉远 86.3%，推近 5.0%，小窗 6.7%，15 个模板都出现，文案配对检查为空，没有不足两行的卡片。同一套句子放在 91.366 秒的时钟上：拉远 85.3%，推近 2.6%，小窗 8.8%。清晰填边比值仍是 0.727 对 0.008，倍率仍是 0.80 / 1.08。

`npm run check`：1241 项，1235 通过，0 失败，6 跳过，vite build 成功。

## 压缩原片上的复核

用户补交了压缩原片（1280×720，127.9 秒，音画差 0.191 秒，sha256 `062e67f83134cdd3721d6fdf4bd32e86d7d610f700af2b05c9bb12b02ff66672`）和原来的转写。没有重跑识别，没有改 VAD，没有改清晰度阈值 0.45，没有把素材入库。

上传转写比这版压缩片的说话能量早大约 0.27 秒。只在工作目录里把这份字表后移了 0.27 秒，审阅 JSON 里已经落在能量上的替换词保持原时间。工作目录词库把转写里断开的 `ag ent` 显示成 Agent。这些都不进仓库。

粗剪结果：4 处删除（语气词 ×3、重说 ×1），16 处停顿，成片 97.80 秒，21 段。这和原来 Paraformer 字表上的 5 处删除、18 处停顿、91.37 秒不是同一份输入。不要把 97.80 写进规则。官方切视频 2923 帧，按保留段估算 2934 帧。试听响度 −16.0 LUFS，真峰值 −4.3 dBTP。

这版草稿的占比：拉远 90.5%（88.49 秒），推近 4.4%（4.31 秒，三次，0.94 / 1.76 / 1.61 秒），小窗 2.0%（2.00 秒，一页文档），结尾 3.1%。文案配对检查为空。没有不足两行的卡片。四句误区各自一屏，顺序跟口播一致。原先那张只有一行的卡片没有再出现，那一句改成单行大字。

关键帧都在拉远：约 12 秒是整句问句，大字和字幕是同一句；约 22.7 秒大字还在滑入，23.2 秒落定成一句；约 42 秒不再推近；约 49.9 秒是单独一句，50.5 秒抓在这句滑出的运动模糊上；约 62 秒不是空卡片。对照两张：约 40 秒把同一句的前后半放在同一幅拉远画面里，后半句大字贴到左边缘；约 75 秒是原先空卡片那一句的单行大字。清晰填边比值 0.56–1.13，压缩没有让检查失败。

中段样片是这版成片的 36–56 秒，不是全片。用户后来看过这些帧：占比可以，补边镜像了人、同屏文字重复、后半句大字出界且偏早。后续改动在 P1-v11。点头之前不要渲全片，不要合并 PR #4。
